Players on any `0.1.x` can play together: this release changes neither the IPC nor the Peer protocol. Only the Helper and the DLL changed.

**What's new: three opt-in speed switches, all off by default**

Nothing changes unless you turn a switch on. They are for testers on slow or lossy links; none has been tried in a real game yet.

- **`DATALINK_EARLY_ACKS=1`** (Helper). In a two-player game, the Helper answers each reliable message at once instead of waiting a round trip. Games of three or more players play as in 0.1.3. Only the host needs it.
- **`DATALINK_FAST_WAKE=1`** (the game, read by the DLL). The DLL wakes the game as soon as a message is sent and polls every 1 ms instead of 10 ms.
- **`DATALINK_CONGESTION=bbr`** (Helper). Uses the BBR congestion controller instead of Cubic, which should hold up better on random Wi-Fi loss. `cubic` and `newreno` also work. Only the host needs it.

The log script takes them as options: `datalink-mp-collect-logs --early-acks --fast-wake --congestion bbr`. See [docs/players/collecting-logs.md](https://github.com/BlinkingApe/datalink-mp/blob/main/docs/players/collecting-logs.md).

Also new: the page shows whose game is working on a turn sync ("Syncing turn N: your friend's game is working out the turn") and the tab title says "Syncing…" once a sync passes 10 seconds; the Helper log gets hop times, Early ack counts and link figures for every turn sync.

**Testers: what to send back**

- Say which switches you turned on (the log script writes them to `switches.txt`).
- Send the Helper's **log** and the game's **DLL log** after a game, and the **capture** when asked.
- Report any hang, a `SEND MESSAGE TIME EXPIRED` message, or a game that behaved differently from one without the switches.
